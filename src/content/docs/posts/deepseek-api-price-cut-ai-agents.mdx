DeepSeek has announced a major API price reduction, with prices for its V4-Flash series falling by as much as 60%.

The new pricing takes effect on September 10, 2026 at 12:00 PM Beijing Time. For developers building AI agents, coding agents, and API-powered applications, the change could significantly reduce inference costs.

## DeepSeek API Prices Drop Again

DeepSeek's latest pricing adjustment brings significantly lower prices during off-peak hours.

The new off-peak pricing includes:

- Input with cache hit: ¥0.02 per 1M tokens
- Input with cache miss: ¥1 per 1M tokens
- Output: ¥4 per 1M tokens

Peak-hour pricing remains twice the off-peak rate.

The biggest change is the cache-hit input price, which drops from ¥0.05 to ¥0.02 per million tokens, representing a 60% reduction.

For developers running large-scale AI workloads, lower input costs can make a noticeable difference in overall API spending.

## Why Lower API Prices Matter for AI Agents

Lower model prices are particularly important for AI agents.

Unlike a simple chatbot, an AI agent may make multiple model calls during a single task. It may need to understand a request, generate code, call tools, read information, perform reasoning, and review its own output.

As agent workflows become more complex, inference costs can quickly become a significant part of the infrastructure bill.

Lower API prices give developers more room to experiment with longer workflows, more model calls, and more advanced AI applications.

## Peak and Off-Peak Pricing

DeepSeek's pricing also highlights the growing importance of peak and off-peak inference.

DeepSeek defines weekday peak periods from 9 AM to 12 PM and from 2 PM to 6 PM Beijing Time. The remaining hours are considered off-peak.

For workloads that do not require immediate processing, developers can potentially run batch jobs, evaluations, background tasks, and other workloads during lower-cost periods.

This means AI cost optimization is becoming more than simply choosing a model.

Developers also need to consider when a model is used and how each request is routed.
